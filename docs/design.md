# Архитектура

## Продукт

ClearYourWin — репозиторий для работы ИИ-агента с конкретным Windows-ПК.
Агент интерпретирует данные и учитывает предпочтения владельца. PowerShell-инструменты
дают проверяемые факты и исполняют узкие, явно выбранные действия. Постоянный агент не нужен.
Цель оптимизации — меньше лишней фоновой работы и ожидания в задачах пользователя;
не максимум свободной ОЗУ сам по себе: Windows использует свободную память как кэш.

Поток: `PROMPT → Collect → JSON → Analyze → план → разрешённое действие → журнал → повторный замер`.

## Компоненты

- `lib/WindowsCleaner.psm1`: сбор секций, ограниченный файловый обход, правила анализа, JSON I/O.
- `lib/Startup.psm1`: предпросмотр, журнал и изменение отдельной записи HKCU Run.
- `tools/`: отдельные входные точки для агента; обычные параметры, ошибки PowerShell, JSON.
- `reports/`: локальные снимки; `backups/`: журналы обратимых изменений.
- `tests/`: автономные проверки без Pester и прав администратора, с синтетическими данными.

Сбор не запрашивает elevation автоматически. CIM-запросы имеют OperationTimeoutSec 15;
это ограничение операций провайдера, а не жёсткий общий deadline процесса. Недоступная секция
получает `status=error`, частично доступная — `partial`. Остальные секции продолжают работу.
Нельзя интерпретировать `items=[]` вместе с ошибкой как "ничего не найдено".

## Контракт снимка, schemaVersion = 1

Корень: `schemaVersion`, `collectorVersion`, `startedAtUtc`, `finishedAtUtc`, `computerName`,
`userSid`, `isAdministrator`, `options`, `sections`.
Каждая секция: `status` (`ok|partial|error`), `items` (всегда массив), `errors` (массив строк).
Даты — UTC ISO 8601, размеры — байты, CPU — процент общей мощности логических CPU (0–100).

| Секция | Источник / смысл |
| --- | --- |
| system | Win32_OperatingSystem и Win32_ComputerSystem: ОС, доступная/полная видимая память, CPU |
| processes | Два Win32_Process, дельта KernelModeTime + UserModeTime / время / число CPU; имя, PID, путь, WorkingSet, PrivateBytes, ThreadCount |
| threads | По запросу: до 256 потоков каждого из 10 наиболее нагруженных процессов; состояние и накопленное CPU, без стеков |
| startup | HKCU/HKLM Run/RunOnce, WOW6432Node, две Startup-папки, задания с Boot/Logon-триггерами |
| services | Win32_Service, включая State, StartMode, PathName, ProcessId |
| drivers | Win32_PnPSignedDriver: версия, поставщик, подпись и привязка к DeviceID |
| systemDrivers | Win32_SystemDriver: загруженные/остановленные kernel-драйверы |
| devices | Win32_PnPEntity: Present, Status и ConfigManagerErrorCode; отсутствие Present сохраняется как null |
| disks | Локальные Win32_LogicalDisk: объём и свободное место |
| applications | Uninstall-реестр HKCU/HKLM, обе разрядности; без выполнения UninstallString |
| defender | Get-MpComputerStatus: состояние защиты и актуальность баз; не сканирование |
| diskScan | Размер просмотренных файлов, старый TEMP как кандидат, потенциально исполняемые файлы, полнота/ошибки |

Автозапуск — инвентаризация источников, не точное воспроизведение вкладки Task Manager.
Не все механизмы persistence покрыты (WMI subscriptions, Winlogon, shell extensions и т. д.).
Приложения из реестра не включают все portable/MSIX-приложения. ОЗУ процессов содержит общие
страницы: сумму WorkingSet нельзя считать фактическим суммарным расходом физической памяти.
CPU измеряется за SampleSeconds + время перечисления; новые/исчезнувшие процессы имеют null,
PID сопоставляется вместе с CreationDate. PID 0 исключён из рейтинга нагрузки.
Threads.CpuTotalSeconds — накопленное CPU, не текущая нагрузка потока. Недоступные/завершившиеся
процессы отражаются в ошибках. Число потоков не означает загрузку всех ядер.

## Файловый обход

По умолчанию только TEMP текущего пользователя и Windows Temp. Дополнительные корни
передаются явно через ScanRoot, они заменяют стандартные. Лимиты на каждый корень: число
просмотренных записей и время, глубина 32. Reparse points не обходятся; проверяются также
предки корня. До 100 примеров старых файлов и исполняемых расширений на корень. Каталоги
перечисляются лениво; отчёт не накапливает список всего диска. Недоступные ветки, ссылки,
лимиты и смена файлов во время обхода не скрываются.
Кандидаты TEMP — обычные файлы старше 7 дней внутри стандартных TEMP-корней. Явно заданный
произвольный каталог не становится мусором. Неизвестные файлы не удаляются.
Это снимок файловой системы, не форензика: параллельная замена каталогов возможна; перед
будущей очисткой обязательно повторно проверить путь/тип/возраст каждого файла.

## Анализ и изменения

Правила анализа объяснимы: низкая доступная память, высокая CPU-нагрузка за интервал,
мало места, PnP-ошибка, выключенная защита, просроченные базы, исполняемые файлы в TEMP.
Каждая рекомендация содержит `id`, `severity`, `category`, `evidence`, `recommendation`.
Ни одно правило не выдаёт заключение "вирус". Секции с ошибками формируют предупреждения.

Единственный изменяющий инструмент v0.1 — отдельная запись HKCU Run. По умолчанию предпросмотр;
нужен Apply. ShouldProcess поддерживает WhatIf/Confirm. До удаления значения — новый JSON-журнал
с компьютером, SID, именем, RegistryValueKind и точной исходной строкой. Разрешены String и
ExpandString. Восстановление ограничено тем же ПК/SID и HKCU Run; существующее значение не
перезаписывается. После изменения значение перечитывается. Журнал хранится отдельно от снимка.
Само наличие журнала не доказывает, что отключение завершилось: при восстановлении проверяется
текущее значение. Параллельное изменение автозапуска другим ПО возможно; не запускайте операции
одновременно. Эти инструменты не являются политикой защиты от злоумышленника с правами пользователя.

## Подключение и приватность

Локальный запуск или существующая PSSession. Сборщик передаётся как текст доверенного локального
модуля и исполняется в памяти удалённой сессии; удалённые временные файлы не создаются.
Ни один путь/команда из JSON не исполняется. Отчёт возвращается JSON-строкой, чтобы избежать
изменения вложенных структур сериализацией remoting. Учётные данные не сохраняются.
Интернет-подключение, собственный демон и удалённые изменения не входят в первую версию.

Полный отчёт остаётся локально. Не собираются содержимое документов, память процессов,
пароли и сетевой трафик. Команды автозапуска/служб и названия ПО всё равно требуют бережного хранения.
