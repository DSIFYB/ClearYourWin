# Очистка и обслуживание

## Рабочий сценарий

1. Снимок системы и анализ узкого места.
2. План очистки или предпросмотр одной операции обслуживания.
3. Выбор владельца: точное действие/список, ожидаемый эффект, ограничения отката.
4. Apply с журналом. WhatIf сохраняет режим без изменений даже вместе с Apply.
5. Анализ результата, повторный снимок при сопоставимой нагрузке, Compare-Snapshots.

Разрешение разработать инструменты не является разрешением чистить рабочий ПК во время разработки.
Применяющие проверки выполняются только на специально созданных файлах внутри tests/.

## TEMP-план, schemaVersion=1, kind=temp-cleanup

План хранит planId, ПК/SID, scope, createdAtUtc/expiresAtUtc, minAgeDays, maxBytes/candidateBytes,
roots, items, статистику обхода и ошибки. Каждый item содержит root и file: Path, Length,
FileId (volume serial + file index), LastWriteTicks, CreationTicks. Ticks — строки для точности
при передаче JSON через инструменты, работающие с числами IEEE 754. Имена и пути — данные.
Не запускайте и не интерполируйте их в shell-команды.

По умолчанию: UserTemp, возраст 7 дней, до 1000 файлов, 2 GiB, 10000 записей и 10 секунд обхода.
Лимиты регулируются: до 5000 файлов, 10 GiB, 100000 записей, 120 секунд, глубина 32.
Временной лимит проверяется между операциями I/O, это не жёсткий таймаут зависшего провайдера.
Корни — LocalApplicationData/Temp и Windows/Temp, определённые Windows для текущей учётной записи.
Произвольные ScanRoot и TEMP/TMP не расширяют область разрешённого удаления. Перенесённый или
связанный TEMP может быть недоступен для автоматической очистки: отказ предпочтительнее расширения
корней. Каталоги, UNC/сетевые/device-пути, alternate data streams и неоднозначные пути не удаляются.

Кандидат должен быть обычным локальным файлом без reparse point, старше порога по времени создания
и записи. Запускаемые расширения, системные, read-only, offline-файлы и hardlinks исключены.
Очистка не следует в профили браузеров, Downloads, DriverStore или WinSxS. WindowsTemp может
потребовать администратора; инструмент не повышает права сам и не берёт владение файлами.
`complete=false` означает лимит, исключения политики, недоступные ветки или иные пропуски;
точный сохранённый список всё равно можно применить после просмотра. errors содержит до 30 примеров.

Перед удалением: проверка схемы, возраста плана/файлов, ПК/SID, списка стандартных корней,
уникальности путей и суммы размеров. C#-помощник открывает и удерживает цепочку каталогов от
корня диска без разрешения их удаления/переименования; reparse points отклоняются. Файл открывается
без разрешения записи/удаления другим процессом, сверяются конечный путь и метаданные/идентификатор.
Удаление выполняется SetFileInformationByHandle на этом же дескрипторе, не по повторно разрешённому
пути. Подмена ссылкой, изменение файла, занятость или отказ доступа дают skipped, без force/retry.
Эти проверки не превращают процесс с правами администратора в изолированную границу безопасности.

Журнал создаётся новым файлом вне корней очистки. До обработки файла синхронно записывается intent,
затем deleted/skipped. Сбой записи журнала прекращает дальнейшую очистку. После прерывания intent
без результата означает неопределённость: проверьте текущий файл, не считайте его удалённым.
Повторное применение перепроверяет идентификаторы; не удаляет свежие замены под старым именем.
deletedBytes — логический размер отмеченных к удалению файлов; освобождение места может задерживаться
из-за открытых читателей, сжатия, снимков и фоновой активности Windows. Журнал не содержит содержимое
файлов. Восстановление окончательно удалённых файлов проект не предоставляет.

## Каталог обслуживания

Invoke-Maintenance.ps1 принимает только Action из фиксированного списка. Нельзя передать произвольный
EXE, команду или аргументы. DriveLetter — строго одна буква, только для операций тома.
Apply нужен также для длительных диагностических DISM/SFC-запусков; без него — описание действия.

| Action | Штатная команда | Эффект/ограничение |
| --- | --- | --- |
| AnalyzeComponentStore | DISM /Online /Cleanup-Image /AnalyzeComponentStore /NoRestart | Анализ, не очистка |
| CleanComponentStore | DISM /Online /Cleanup-Image /StartComponentCleanup /NoRestart | Удаляет заменённые компоненты без 30-дневного ожидания планировщика; автоматического отката нет; ResetBase запрещён |
| AnalyzeVolume | Optimize-Volume -DriveLetter X -Analyze | Анализ одного тома |
| OptimizeVolume | Optimize-Volume -DriveLetter X | Windows выбирает операцию; не форсируется Defrag на всех носителях; отката расположения данных нет |
| FlushDns | Clear-DnsClientCache | Сбрасывает локальный resolver cache; не меняет DNS-сервер, VPN, сеть и конфигурацию адаптера |
| VerifySystemFiles | SFC /verifyonly | Проверка, без ремонта системных файлов |

DISM, SFC и операции тома требуют заранее повышенной PowerShell-сессии. Поддержка зависит от версии
Windows, модулей Storage/DnsClient и политик. Ошибки сохраняются и возвращаются как ошибки команды.
Средства запускаются по абсолютным системным путям либо module-qualified именам. Вывод EXE
сохраняется как stdout/stderr, вывод cmdlet/verbose — output.txt. request.json пишется до запуска,
result.json — после; при прерывании остаётся started без итогового результата. Процесс обслуживания
может продолжить работу после закрытия оболочки: сначала проверьте его состояние, не запускайте второй.
Код 3010 фиксируется как rebootRequired; автоматической перезагрузки нет. Успешное завершение
утилиты не доказывает целостность Windows: читайте вывод SFC/DISM и штатные журналы.

Не очищаем Prefetch/ОЗУ/реестр "для ускорения", не отключаем защиту, обновления, файл подкачки,
службы или драйверы по универсальному списку. Настройка служб/удаление приложений остаётся отдельной
задачей с анализом зависимостей и приёмкой. Уже существующие инструменты HKCU Run дают обратимую
оптимизацию фонового запуска пользовательских приложений.

## Сравнение

Compare-Snapshots проверяет версию, ПК/SID и порядок дат. Выводит signed delta свободной физической
памяти, суммы доступных CPU-замеров процессов и места на томах с той же буквой/размером.
Это не проверка аппаратной идентичности тома: при замене/переподключении носителей не делайте
вывод о количестве очищенного места по одной букве. Неполные данные отмечаются предупреждениями;
отсутствующая CPU/память остаётся null. При разных sampleSeconds — предупреждение.
Сумма CPU не включает новые/исчезнувшие процессы и не заменяет счётчик общей загрузки.
Два снимка не доказывают причинную связь с изменением: повторяйте замеры с одинаковой нагрузкой.
