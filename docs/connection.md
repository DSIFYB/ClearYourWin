# Подключение к Windows-ПК

## На том же компьютере

Скопируйте весь репозиторий, откройте PowerShell в папке проекта, запустите Collect-Snapshot.ps1.
Можно передать агенту только созданный JSON, предварительно просмотрев его на личные сведения.
Это основной сценарий; не требует сетевых портов.

## Уже настроенное PowerShell Remoting

Работайте только с явно указанным ПК, к которому владелец предоставил доступ.
Настройку WinRM/сертификатов/доступа выполняет владелец или администратор вне этого инструмента.
Не публикуйте WinRM в интернет и не используйте wildcard TrustedHosts/Basic без защиты.
Для сетей вне домена используйте согласованный HTTPS endpoint или частную доверенную сеть.

Из интерактивной PowerShell-сессии оператора:

```powershell
# Пример для существующего HTTPS endpoint. Пароль вводится интерактивно, не в файле.
$credential = Get-Credential
$session = New-PSSession -ComputerName 'pc.example.local' -UseSSL -Credential $credential
try {
    ./tools/Collect-RemoteSnapshot.ps1 -Session $session
} finally {
    Remove-PSSession -Session $session
}
```

Для доменного Kerberos используйте утверждённый администратором способ New-PSSession.
Скрипт принимает уже созданную сессию, не меняет транспорт, firewall, политики или права.
Не включайте в журнал объект Credential. Удалённый сбор исполняет только локальный код из lib/.
Убедитесь, что копия проекта доверенная, как перед запуском любого скрипта.

HKCU, приложения пользователя, Startup и TEMP в отчёте относятся к пользователю удалённой сессии,
а не обязательно к человеку за экраном. Сверьте userSid. Инструменты изменения автозапуска
в v0.1 запускаются локально в целевом профиле; удалённое применение не реализовано.

Если соединение не настроено, используйте ручной запуск и передачу отчёта. Не сканируйте сеть
и не пытайтесь обходить ограничения доступа. Подробнее: [требования Microsoft](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_remote_requirements).
